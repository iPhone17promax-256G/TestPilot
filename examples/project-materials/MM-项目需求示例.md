# MM 项目需求示例

本文件用于演示 AIQA 的项目资料库。它保存到 MM 项目后，不需要在每次对话中重新附上。这里列出的验收要求只覆盖演示范围，不代表 MM 的完整接口目录。

## 背景与边界

MM 是用于演示接口、Web UI 和性能测试的被测系统。AIQA 与 MM 的账号不同；本文件没有有效账号或密码，也不要求访问用户的真实工作数据。测试应使用明确不存在的账号验证拒绝行为，成功登录流程需要另行提供测试凭据。

需求应作为测试预期的依据。当前页面或接口实际返回什么，只能作为观察结果，不能为了通过测试而修改本文件中的预期。本次资料库验收只要求读取、解释文档，不需要编写或运行测试。

## 接口验收要求

### 健康检查

- 方法：GET。
- 路径：`/api/v4/system/ping`。
- HTTP 状态应为 200。
- 返回 JSON 的 `status` 应为 `OK`。
- 应分别检查 HTTP 状态和业务字段，不能只检查请求没有报错。

### 不存在账号登录

- 方法：POST。
- 路径：`/api/v4/users/login`。
- JSON 请求体包含 `login_id` 和 `password`，使用演示用不存在账号，不包含真实凭据。
- 预期 HTTP 状态为 401；不能因为请求已送达就判断登录成功。
- Web 场景应观察登录失败提示，并确认未进入已登录状态。
